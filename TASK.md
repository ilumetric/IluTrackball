# IluMXErgo — задача для ИИ-агента

## Контекст

- Устройство: **Logitech MX Ergo** (трекбол под большой палец), Windows 11 x64.
- Проблема: при движении шарика курсор идёт **ступеньками**, особенно на медленных движениях.
- Прошивка Logitech закрытая, поэтому работаем на уровне ОС: перехватываем движение, обрабатываем своим алгоритмом и отдаём системе.
- Возможные причины ступенек (нужно различать):
  1. **Квантование.** Низкий DPI сенсора × множитель скорости Windows: каждый отсчёт = несколько пикселей.
  2. **Stick-slip.** Шарик залипает на опорах и срывается: паузы, потом скачок.
  3. **Неравномерный опрос.** Bluetooth или помехи ресивера: рваные интервалы между пакетами.
- Rust уже установлен (`.cargo`, `.rustup`).

## Цель

Windows-утилита на Rust из двух частей:

1. **ilumx-probe** — диагностика: пишет сырые события трекбола и говорит, какая из причин выше реальна.
2. **ilumx-filter** — фильтр движения: перехватывает ввод MX Ergo, применяет выбранный алгоритм, режимы переключаются на лету.

Плюс **ilumx-replay** — офлайн-прогон алгоритмов по записанным логам, чтобы настраивать параметры без живого перехвата.

## Структура

Cargo workspace:

```
crates/
  core/     # алгоритмы и аккумулятор, без зависимостей от Windows, покрыт тестами
  probe/    # Raw Input логгер + анализ
  replay/   # CSV in -> алгоритм -> CSV out + HTML/SVG график
  filter/   # Interception: перехват, обработка, инъекция
```

## Этап 1 — ilumx-probe (делать первым, без драйверов)

- Raw Input API: `RegisterRawInputDevices` с `RIDEV_INPUTSINK` (скрытое окно), обработка `WM_INPUT`.
- Список мышей через `GetRawInputDeviceList` / `GetRawInputDeviceInfo` (имя устройства, VID `046D` = Logitech). Пользователь выбирает устройство, по умолчанию берётся Logitech.
- Лог в CSV: `t_qpc_us, dx, dy, buttons, wheel`.
- Сценарии записи (подсказки в консоли): «медленно веди по горизонтали 10 с», «медленно по вертикали», «быстрые движения», «по кругу».
- Анализ и отчёт (консоль + `report.md`):
  - интервалы между пакетами: медиана, p95, джиттер, доля пропусков > 2× медианы → **опрос**;
  - распределение |dx|, |dy| на медленных участках: доля ±1 и 0 → **квантование**;
  - паттерн «пауза ≥ N мс → скачок ≥ M отсчётов» при медленном движении → **stick-slip**;
  - текущие настройки Windows: `SPI_GETMOUSESPEED` (скорость 1–20, где 10 = 1:1) и `SPI_GETMOUSE` (Enhance Pointer Precision). Предупреждать, если скорость выше 10;
  - итог: какая гипотеза наиболее вероятна и что сделать (чистка опор, скорость Windows 10/20 + DPI в Options+/OpenLogi, ресивер вместо Bluetooth).

## Этап 2 — ilumx-replay

- Вход: CSV из probe. Выход: CSV после алгоритма + HTML-страница с графиками позиции до/после по времени (X и Y) для сравнения режимов и параметров.
- Это основной инструмент настройки алгоритмов, гонять его до живого фильтра.

## Этап 3 — ilumx-filter

### Перехват
- Драйвер **Interception** (oblitum/Interception). **Агент драйвер НЕ устанавливает**: установка требует прав администратора и перезагрузки, её делает пользователь. Агент пишет пошаговую инструкцию в README.
- Rust: проверить актуальность crate `interception`. Если он заброшен, сделать тонкий FFI к `interception.dll`.
- Обрабатывать **только MX Ergo** (по hardware id). Остальные мыши и все клики, колесо и кнопки пропускать без изменений.

### Пайплайн
`dx,dy (int)` → виртуальная позиция (f64) → алгоритм → разница с прошлым выходом → **субпиксельный аккумулятор** → `int dx,dy` → инъекция.

Важно: у сглаживающих фильтров есть «хвост». Когда шарик остановился, событий больше нет, а отфильтрованная позиция ещё не догнала реальную. Нужен тикер (~500–1000 Гц), который дотягивает остаток до сходимости и засыпает, когда разница < 0.5 px. Хвост не должен тянуться дольше заданного тайм-аута.

### Режимы (`core`)
- `passthrough` — как есть (эталон задержки).
- `one_euro` — One Euro Filter (`min_cutoff`, `beta`, `d_cutoff`). Основной кандидат: сильное сглаживание на медленных движениях, минимальный лаг на быстрых.
- `ema` — простое экспоненциальное сглаживание, для сравнения.
- `accel` — кривая ускорения: множитель от скорости, варианты linear / power / таблица точек (по аналогии с RawAccel).
- `precision` — множитель < 1 с субпиксельным аккумулятором, для точной работы.
- Режимы комбинируются: сглаживание → кривая.

### Управление
- Конфиг `ilumx.toml` рядом с exe, с горячей перезагрузкой. Пресеты режимов с параметрами.
- Переключение пресетов горячей клавишей (по умолчанию `Ctrl+Alt+F11`). Опционально: удержание кнопки трекбола (настраивается).

### Безопасность — критично
Если процесс завис, держа захват мыши, курсор перестанет двигаться. Обязательно:
- **Аварийный выход** — `Ctrl+Alt+Pause` (через Interception на клавиатуре): немедленно отпустить захват и выйти;
- поток обработки отдельно от тикера. Любой `panic` → режим passthrough или корректное освобождение драйвера;
- тайм-аут хвоста фильтра;
- никогда не терять и не задерживать клики.
- В README предупредить: драйвер Interception может не нравиться античитам в играх.

## Этап 4 — опционально

- Трей-иконка с текущим режимом и автозапуском.
- Связка с OpenLogi CLI: вместе с пресетом переключать DPI устройства (если MX Ergo его отдаёт по HID++).

## Критерии готовности

- `cargo build --release` проходит. `probe` и `replay` работают без драйверов.
- Юнит-тесты `core`: детерминированные, на синтетике и на записанных CSV (сходимость хвоста, отсутствие дрейфа аккумулятора, passthrough бит-в-бит).
- `filter`: в режиме passthrough задержка не ощущается. Пресеты переключаются. Аварийный выход проверен.
- README: сборка, установка Interception, сценарий «записал → посмотрел отчёт → подобрал параметры в replay → включил filter».

## Правила работы

- Порядок: этап 1 → попросить пользователя записать логи и показать отчёт → этап 2 → этап 3. Не прыгать сразу к драйверу.
- Код и комментарии на английском, общение с пользователем на русском.
- Не устанавливать драйверы и не менять системные настройки Windows. Только предлагать.
- Систему контроля версий не инициализировать и не коммитить без запроса.
